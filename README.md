# VoltTrack (Expo / React Native)

## Beginner's Project Guide

VoltTrack is a mobile attendance tracker for a college semester. You can set the
semester dates and minimum attendance target, mark each day as attended, bunked,
or an official holiday, and see the calculated percentage and safe bunks left.
The optional timetable is an independent weekly reference for recurring classes
and times. It never changes attendance calculations or the daily attendance log.

### How The Project Is Organized

`App.tsx` is the starting point. It creates the app provider (the shared data
store), draws the common header, and chooses which screen is visible.

`src/types.ts` describes the shapes of the data. It is like a rulebook saying
what a day log, lecture, timetable, and complete app state must contain.

`src/context/AppContext.tsx` is the app's shared brain. It loads saved data,
saves changes, calculates statistics, and exposes actions such as adding a
lecture or marking a day as attended. Screens use `useApp()` to access it.

`src/storage.ts` saves and loads the app state using Android/iOS local storage.
This means data remains after the app is closed, but it is stored only on the
device until the user exports a backup.

`src/utils/calculations.ts` contains the day-based attendance mathematics.
`src/utils/notifications.ts` schedules the daily native reminder using Expo
Notifications.

`src/theme.ts` contains shared colors and the attendance progress gradient.

`src/components/` contains reusable visual pieces: the summary card, progress
ring, glass card background, calendar, bottom navigation, and attendance modal.
These pieces do not own the whole app; they receive data and call shared app
actions.

`src/screens/` contains the four user-facing tabs:

- `TrackerScreen.tsx`: calendar and the day/lecture logging modal.
- `TimetableScreen.tsx`: recurring lectures for each weekday.
- `AnalyticsScreen.tsx`: bars and totals explaining the calculation.
- `SettingsScreen.tsx`: semester dates, target percentage, reminders, and JSON backup/restore.

`assets/` contains the app icon, adaptive Android icon, splash image, and web
favicon. These are binary images, so they cannot contain source-code comments.

`app.json` is Expo's app identity and native-build configuration. It names the
app, selects icons and splash assets, chooses the Android package name, and
requests notification permissions.

`babel.config.js` tells Babel, the JavaScript/TypeScript transformer, to use the
Expo preset. `tsconfig.json` enables TypeScript and strict type checking.
`package.json` lists commands and libraries; `package-lock.json` locks the exact
installed dependency versions and should normally be generated by npm.

`www/index.html` is the older standalone web version of VoltTrack. It contains
its own HTML, Tailwind styling, and browser JavaScript using `localStorage`.
The current Expo mobile entry point is `App.tsx`, not this file.

`android/` is the native Android wrapper generated/configured for building the
app. Gradle files describe Android dependencies and build tasks, the manifest
declares Android components and permissions, Kotlin files start the native app,
and `res/` contains Android icons, colors, styles, and splash resources. Folders
such as `android/app/build/` and `.expo/` are generated caches/build products;
they are not hand-written app features and should not be manually documented or
edited.

### Android Folder Details

`android/gradlew` and `android/gradlew.bat` are the Gradle wrapper launchers for
macOS/Linux and Windows. `android/gradle/wrapper/` contains the wrapper version
and its binary launcher. `gradle.properties` stores build switches, while
`settings.gradle` finds React Native/Expo plugins and includes the app module.
The top-level `build.gradle` supplies shared Android SDK and Kotlin versions.

`android/app/` is the actual Android application module. Its `build.gradle`
defines the package name, SDK levels, debug/release builds, signing, and native
dependencies. `capacitor.build.gradle` is generated Capacitor integration
configuration, and `proguard-rules.pro` contains release-code shrinking rules.
`debug.keystore` is the development signing key and is not a production key.

`android/app/src/main/java/.../MainActivity.kt` is the Android screen that hosts
the React Native app. `MainApplication.kt` starts React Native, Expo modules,
and automatically linked native packages. `AndroidManifest.xml` registers these
components and declares permissions such as notifications and alarms.

Inside `android/app/src/main/res/`, `drawable*` folders contain splash images or
Android XML drawables at different screen densities. `mipmap*` folders contain
launcher icons at different densities. `values/` and `values-night/` hold names,
colors, and themes. `xml/config.xml` holds native configuration. The
`android/app/src/debug/` manifest adds debug-only Android settings.

`android/app/src/main/assets/` contains the generated Capacitor configuration
and the bundled web assets. `android/capacitor-cordova-android-plugins/` is a
generated compatibility module for Cordova plugins; its manifest, Gradle file,
and `cordova.variables.gradle` are build wiring rather than attendance logic.
Empty `.gitkeep` files simply preserve otherwise-empty folders in version control.

`android/app/build/`, `android/build/`, `.expo/`, and nested generated folders
are temporary outputs from Android/Expo builds. `package-lock.json` is npm's
machine-generated dependency lock file. JSON files (`app.json`, `tsconfig.json`)
and image files cannot contain normal comments without breaking their format,
so their purposes are documented here instead.

### Simple Data Flow

1. The app starts in `App.tsx` and wraps everything in `AppProvider`.
2. The provider loads the previous state from `AsyncStorage`.
3. A screen calls an action, for example `setDayLog`.
4. The provider updates state and automatically saves it.
5. `computeStats` recalculates the percentage, target minimum, and safe bunks.
6. React redraws the calendar, summary card, and analytics with the new values.

The comments in the source files mark each of these feature groups for readers
who are new to coding.

Full mobile rebuild of the VoltTrack web app, plus one new feature:

**Independent Weekly Timetable** — set up recurring classes and times in the
Timetable tab. The timetable is for reference only: subjects do not appear in the
daily attendance modal and adding classes never changes attendance calculations.
Weekly timetable data is included in JSON backups and restored with the rest of
the app state.

## Setup in Termux

```bash
cd ~
unzip volttrack-app.zip
cd volttrack-app

# Install deps — legacy-peer-deps avoids the peer resolution errors we hit before
npm install --legacy-peer-deps

# Let Expo align every "*" package to the version that matches your SDK
npx expo install --fix
```

## Run / preview

```bash
npx expo start
```
Scan the QR with Expo Go to preview on your phone. Note: `expo-notifications`
scheduled/repeating alarms need a **dev client or a real build** — they won't
fully work inside Expo Go.

## Build the Android APK/AAB with EAS

```bash
npm install -g eas-cli
eas login

export EAS_SKIP_AUTO_FINGERPRINT=1
eas build -p android --profile preview
```

If you don't have an `eas.json` yet:
```bash
cat > eas.json << 'EOF'
{
  "cli": { "appVersionSource": "remote" },
  "build": {
    "preview": { "distribution": "internal", "android": { "buildType": "apk" } },
    "production": {}
  }
}
EOF
```

## What matches the original web app

- Same dark glass / lavender-pink aesthetic (approximated with `expo-blur` for the
  glassmorphism instead of CSS `backdrop-filter`)
- Same 3 core screens: Tracker (calendar), Analytics, Settings
- Same day states: Attended / Bunk / Official Off / Clear
- Same "Projected Final %" logic, "Safe Holidays/Bunks Left" logic
- Same Backup/Restore (JSON export/import — via `expo-file-system` + `expo-sharing`
  + `expo-document-picker` instead of browser download/upload)
- Same daily reminder concept (via `expo-notifications` instead of Capacitor
  LocalNotifications, since this is a pure Expo project)

## What's new

- **Timetable tab** (4th nav item) — define recurring lectures per weekday
- Weekly timetable remains available as a separate planning feature
